# 截图首次使用优化：对抗复核

日期：2026-11-11。范围：本聊天新增的截图预加载、STA 调度、复制日志、测试及性能结论。保留其他聊天正在进行的文件传输、资料库和主窗口改动。

结论：代码与本机受控回归通过；原始故障的真实环境验收仍为 BLOCKED，不能宣布其他电脑的偶发丢图已修复。

## 确认的问题及处置

### 1. P2：合成预加载与真实剪贴板写入发生无用的锁竞争，已修复

`SnipClipboard.PrepareAsync` 先前借用了 `WriteAsync`，因此取得了真实剪贴板写入的全局信号量。它只准备本地图像，并不需要这个锁。真实写入长时间不返回时，预加载会跟着等待，进而拖住后续启动准备；反过来，预加载持锁时真实复制也需要等待。

新增 `SyntheticPreparationDoesNotWaitForAnUnrelatedClipboardWrite`，在注入的真实写入回调被阻塞时启动合成预加载。修改前 1.5 秒内不能完成，断言失败；失败后测试释放写入并回收两条任务，没有留下阻塞线程。

修复：预加载直接在自身 STA 线程完成本地准备，不走真实写入信号量。真实复制继续使用既有信号量。修复后新增测试及相关回归通过。

### 2. 性能结论的基线不够贴近日常启动顺序，已纠正

前一轮约 339ms 的首次构造数字来自只加载资源、尚未构造主界面的独立进程。日常应用先打开主界面，部分 WPF 初始化已经发生，因此该数字不能当作用户实际首次截图延迟或优化收益。

在保留的探针副本中增加 `--resident`：用虚构资料先构造、布局并关闭主界面，再测截图；没有创建可见窗口、读取用户资料或访问系统剪贴板。

| 模拟主界面已初始化的条件 | 首次截图构造 | 首次复制流程 | 第二次构造 | 第二次复制流程 |
| --- | ---: | ---: | ---: | ---: |
| 修改前源码快照 | 28.4ms | 28.8ms | 5.6ms | 16.1ms |
| 修复后、完成截图预加载 | 5.7ms | 14.7ms | 8.0ms | 13.9ms |

这是单次合成场景采样，不包含真实 HWND 首帧、GPU 合成、桌面捕获、OLE 写入、剪贴板读回或历史落盘，不提供百分位或跨机器收益保证。较早另一次采样和 UI 构建并行，可能有资源争用，因此不用于性能对比。历史表已补充条件，并更正日志目录说明。

## 其余复核结果

- 预加载只创建小尺寸合成像素、本地 DataObject 和 PNG 编码对象，不调用系统剪贴板 Get/Set，也不发布合成图片到历史。
- `RunStaAsync` 的启动和清理不等待调用方 UI 上下文；实际异步重试仍回到同一个 STA Dispatcher。未引入长期驻留复制线程。
- 日志仅记录尺寸、毫秒数、异常类型及 HRESULT，不记录图片、剪贴板文字、路径或原始异常信息。
- 真实复制的逐像素读回、异常重试、全局串行化和失败保留选区没有被删除或放宽。
- 本次复核未确认其他产品代码回归；没有据此推断所有真实场景正常。

## 全部剩余问题与未验证项

1. **原始丢图尚未闭环**：其他电脑“第一次流程结束但无截图结果”未稳定复现，失败机器及失败现场不可用。前一轮现场两次截图实际都成功，外部进程改写剪贴板的元数据记录不能认定为原故障根因。
2. **新构建的真实链路未验收**：未实测实际桌面框选、双击后 `SetDataObject`/OLE 持久化、跨进程粘贴、历史写入及第三方监听争用。前一轮尝试独立 Windows window station 时，系统拒绝创建（Win32 5），本轮未绕过隔离限制，也未读写日用剪贴板。
3. **首次准备未完成的窗口仍存在**：程序立即启动就截图、输入队列一直繁忙、预加载失败时，仍走正常冷路径。预加载移动初始化时机，并未消除工作；UI 控件构造期间也不能保证被输入打断。
4. **闲置与设备差异未验证**：长时间闲置、休眠恢复、低性能电脑、多显示器与混合 DPI 的真实设备首帧、物理输入法和系统钩子行为未验收。受控测试不替代这些场景。
5. **外部剪贴板覆盖边界仍存在**：写后校验只证明当时的图像；其他程序稍后主动替换剪贴板时，本次优化不能保证图片继续保留。预加载不预建真实 OLE 剪贴板连接，也不承诺消除其首次开销。
6. **交付范围**：未运行全仓测试，未更新日常安装版，未提交、推送或发布。本轮 30 个定向通过结果不能表述为完整产品验收。
