# 设备与同步：页内收件（2026-11-11）

本次将上一轮独立收件弹窗改为剪贴板“设备与同步”标签页中的接收页面。

页内收件的初次复核见 [复核报告](File-Receive-Adversarial-Review-2026-11-11.md)；后续独立取消、收件归档与交互补齐见 [最新报告](File-Transfer-Completion-2026-11-11.md)。试用请优先使用最新报告中的 transfer-complete 新包。

## 使用方式

- 发送页面新增“查看接收文件”；接收页面提供“返回发送”，切换不清空待发送文件或接收设备。
- 收到请求后自动唤起剪贴板窗口、恢复最小化状态、切到接收页面并播放系统提示音。等待处理期间临时置顶、保留任务栏入口，失焦不自动隐藏。
- 每个请求独立显示发送设备、传输包名称、易读大小和保存位置选择；选择目录后才能接收，也可直接拒绝。
- 多个设备的请求分别处理。取消、超时、连接中断会移除对应请求；窗口真正关闭时结束未处理请求。处理完成后恢复原来的窗口固定设置。
- 接收完成后显示已收记录及实际保存目录，点击“打开保存文件夹”调用 Windows 资源管理器。目录移动、删除或无权限时显示错误。
- 从接收页拖入文件会切回发送页并加入待发送列表；原列表按路径去重。等待收件不占用发送操作的忙碌状态。
- 已收列表现在使用独立本地归档，每页 50 批，不随最近 100 条普通同步记录淘汰；旧版仍保留的成功收件会自动补入，已经淘汰的记录无法恢复。
- 发送列表支持逐项移除，重试结果在发起窗口展示，待处理卡片显示倒计时。两端更新后支持同设备独立取消；兼容范围见最新报告。
- 打开文件夹失败的提示仅显示在接收页，不覆盖原剪贴板／发送页面的状态。

## 验证结果

以下是最初页内实现的历史证据，当前版本验证以最新报告为准。

- 原实现上的行为回归明确失败：收件请求没有唤起剪贴板页面。
- Debug 与 Release 同步反馈聚合用例各 1 个通过。覆盖真实回环传输、窗口隐藏／显示／最小化自动路由、实际 HWND 置顶状态、页内拒收、选择目录后接收并核对文件内容、发送方取消、双请求分别处理、关闭收件窗口、手动固定状态恢复、切页保留发送列表及设备、拖入文件自动回到发送页。
- 已收记录按钮已渲染；目录不存在时的点击错误路径已运行。后续对抗性复核还实际打开了资源管理器，并通过 Windows Shell 确认精确定位到回环收件保存目录。
- 明暗主题、长请求内容滚动及 460 × 400 最小窗口可操作性有定向断言及渲染证据；原辅助窗口设计聚合用例通过（1 个）。
- 核心定向：113 通过、0 失败、0 跳过。筛选为 `FullyQualifiedName~OverTranslate.Tests.Lan|FullyQualifiedName~UnifiedLanSyncTests|FullyQualifiedName~SyncActivity`。
- 上述验证针对独立源码副本：仓库 HEAD 加本次收件页面改动，排除另一项同时进行的启动预加载及其测试改动。该任务中曾观察到启动预加载的 `Size` 类型歧义编译失败，未修改或撤销其代码。
- 启动预加载代码后续修正后，原工作区的同步反馈聚合用例也通过（1 个，日志 `current-workspace-test.log`）；其他任务改动均保留，交付包仍来自独立源码副本。
- 最终 Release 构建与包内程序集哈希核对结果见构建目录的 `verification.json`；构建和测试日志位于 `artifacts/file-receive-tab-20261111/`。
