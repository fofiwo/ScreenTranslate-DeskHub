# 更新刷新与网络代理交付复核（2026-11-09）

范围：开发目录 `b6725da`、公开源码 `6d607c3` 之后的更新缺陷修复与用户追加的代理设置需求。今天更早的全部任务复核见 [当日对抗性复核](Daily-Adversarial-Review-2026-11-09.md)，其中非更新相关的剩余项继续有效。

## 确认的问题与处置

1. **缓存旧版本绕过重新检查。** 主动检查原本直接打开 `Available`，已有更新窗口也不会替换为更高版本。修复后每次查询，窗口提供“刷新版本”，可直接跨版本升级；同版本保持窗口、失败保留原版本，下载或安装期间禁止替换。WPF 旧行为失败证据为 `refresh-red.trx`，修复后验证检查、刷新失败与恢复、再次跳到更高版本及下载保护。
2. **更新源可能重复读取缓存的 latest 重定向。** 连续请求原 URL 相同，`feed-cache-red.trx` 复现；现在每次清单请求带独立查询参数和禁止缓存头，超时 20 秒。仅清单改为重新获取；安装包继续锁定检测到的版本并由 Velopack 校验。取消无意义的小写 URL 重试，不将一次超时翻倍。
3. **连接错误统一显示、缺少应用代理设置。** 指定本机 HTTP 代理实际读取公开更新源成功，系统代理当时关闭；没有取得旧版失败时的底层异常，因此不把具体异常类型当作已确认根因。新增显式代理设置，区分连接、超时、HTTP 状态和清单读取错误，不输出原始敏感错误内容。
4. **资料库原来写死 10808。** 改为统一的按功能代理设置，取消自动探测端口。未勾选或关闭使用系统默认网络，保持回环接口直连。
5. **交付复核发现的新增边界。** .NET 8 会捕获 `IWebProxy` 异常并尝试无代理连接；无效且已启用的代理现在返回不支持的代理协议，以在 HTTP 层阻断。真实本机 HTTP 夹具验证该路径不会请求默认网络。另验证切换后系统代理认证信息不会交给自定义代理。更新入口专项此前只在特殊分支运行，现在纳入默认完整 WPF 入口。

## 代理设置的实际范围

“设置 → 通用与诊断 → 网络代理”：填写 HTTP、HTTPS、SOCKS5 地址，启用后分别勾选以下八类，点击“保存并应用”：

- 更新：版本清单、安装包、更新说明。
- 翻译：文本、截图、持续翻译、替换翻译，含内置服务、OpenAI、DeepL。
- 词典：取词/查词与释义。
- 语音：在线朗读与音频下载。
- 在线 OCR：百度、OpenAI、自定义远程识别。
- 模型下载：OCR 语言包、漫画模型、运行组件。
- 资料库联网：模型列表、连接检查、AI 整理。
- 诊断上传：用户主动提交时的请求，不自动上传。

保存后作用于已有客户端的后续请求；失败保存回滚设置，不改变实际路由。已发出请求继续完成。启用但不可用时不回退直连；未启用时不修改系统代理。本机 localhost/回环接口直连，LAN 同步独立 TCP 不受影响；外部浏览器和 Windows 管理的下载由各自网络控制。不支持代理地址内账号密码。默认关闭，不擅自选择用户要代理的功能。

设置只新增 `AppSettings.NetworkProxy`（启用、地址、功能位集），保留原子保存和逐字段容错读取；旧设置缺少该组时代理默认关闭。无数据库 schema 或 migration 变更；用临时虚构设置验证序列化/重新读取，不读取个人配置或凭据。
