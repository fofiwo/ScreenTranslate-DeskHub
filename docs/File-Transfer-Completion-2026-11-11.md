# 文件收发补齐与对抗性复核（2026-11-11）

本轮补齐此前报告中的同设备取消、收件记录容量，以及逐项移除、重试反馈、接收倒计时共五项。此前页内收件、自动唤起和临时置顶、发送／接收切换、打开保存文件夹继续保留。这里的本地验证不代表两台物理电脑上的完整验收。

## 功能与兼容边界

| 功能 | 当前行为 | 边界 |
| --- | --- | --- |
| 同设备独立取消 | 等待确认时取消对应请求；发送途中在完整分块边界取消，确认后保留连接，反向传输、剪贴板及下一批可继续。 | 两端须支持新能力。旧版或真实网络失败仍安全断开；数据全部发送、正在保存确认时，迟到的取消可能得到成功结果，不删除已保存文件。 |
| 独立收件记录 | 成功收件单独归档，每页 50 批，可前后翻页；不再随普通同步记录的 100 条上限淘汰。 | 旧版已淘汰的历史无法恢复；这里只保存收件元数据，不保证源目录永远存在。 |
| 逐项移除 | 页内及独立发送选择框每行提供“移除”，保留其他选择和磁盘原文件。 | 页内发送期间禁用列表及移除，防止修改正在发送的批次。没有另加 Delete 快捷键。 |
| 重试结果 | 原同步记录窗口显示选择取消、对方拒收、成功或失败；重试进行时禁用重试按钮。 | 连接变化时仍须重新选择接收设备；实际落盘错误不会被包装成成功。 |
| 请求倒计时 | 接收卡片每秒显示剩余时间，归零拒绝；离开可视树或完成决定后停止定时器。 | 使用卡片创建时的 5 分钟期限，协议计时略早开始；不是双方时钟严格同步的倒计时。 |

## 协议与本地数据

- 在认证后的 `hello`／`paired` 中增加可选 `FileCancellation` 能力。双方支持才使用文件分块及取消；协议版本仍为 3，缺少能力字段的旧端使用原始文件帧。
- 分块长度为 4 字节大端数，最大 65536 字节；`-1` 为取消。拒绝零、非法负数、超出最大分块或剩余长度的长度。取消不截断已开始的分块。
- 新版文件确认走剪贴板逻辑通道，避免反向文件确认正等待人工操作时阻塞取消确认。原文件、资料库、剪贴板的发送队列保留。
- 普通同步记录仍是最近 100 条 `sync-activity.json`。新增 `sync-activity.received.jsonl`，只追加已成功接收文件的元数据；按消息 ID 和设备去重，启动时幂等补入旧记录中尚存的成功收件。
- 归档损坏行跳过并显示警告；追加时先写换行，截断尾行不吞掉新记录。写失败明确提示重启后可能丢失，允许同一收件重试写入。读取失败保留原文件。
- 未涉及 SQL、ORM、RPC 或数据库 migration；既有同步记录字段保持兼容。归档在启动时全量读取元数据，没有声称无限规模无性能代价。

## 复核发现与修复

1. **原取消会断开同设备会话**：修复前回环复现保存在 `baseline-cancel.log`。现在分别验证等待确认取消和双向有效载荷发送中取消；反向批次内容哈希一致，连接版本不变，后续剪贴板与文件继续成功。
2. **收件历史受通用记录淘汰**：改为独立追加归档，验证 125 批收件经历超过 100 条普通事件后仍能翻页、重启恢复、重复加载不重复，旧记录导入及写失败恢复。
3. **双向并发时发送结果被接收进度覆盖**：当前工作区第一次集成测试实际得到“接收中”，而不是本批发送完成；`final-current-workspace.log` 保留失败。根因是调用方等待发送后再读取共享状态栏。`SendFilesAsync` 现在直接返回本批结果，两个调用方均使用返回值，原文件选择和拖放调用方仍可忽略结果。

测试取证也保留以下失败，未归为已修复的产品缺陷：

- 一次运行在 WPF `ImmComposition.OnWmImeRequest_ReconvertString` 中发生 CLR 原生错误 `0x80131506`，见 `final-current-workspace-after-result-fix.log`。收件夹具改为禁用输入法，与已有纯历史回归的隔离方式一致；产品输入法设置未改，真实 IME 问题归因及修复仍未验证。
- 请求完成后恢复失焦收起，目录历史检查不应等待窗口永远保持显示。测试在历史目录验证阶段明确固定、重开并切到接收页，之后取消固定；待处理请求阶段的自动显示、置顶、失焦保持及恢复原设置断言保留。中间失败日志保留，不能解释为最终通过。
