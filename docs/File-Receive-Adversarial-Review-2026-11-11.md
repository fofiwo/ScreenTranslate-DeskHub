## 已确认问题及修复

| 问题 | 触发与影响 | 修复与证据 |
| --- | --- | --- |
| 自动收件唤起沿用旧粘贴目标 | 剪贴板窗口隐藏或最小化时直接接收请求，没有重新捕获原应用目标；之后切回历史执行粘贴可能找不到目标或沿用旧目标。 | `ReceiveFilesAsync` 在隐藏／最小化时捕获目标；已显示窗口保留本次打开的目标。覆盖隐藏、最小化、已显示三种状态，断言跟踪目标，不执行真实粘贴。 |
| 请求结束后原生目录选择器仍打开 | 选择保存目录期间发送方取消、断线或超时触发令牌取消，卡片被移除而原生模态目录选择器仍占用窗口。 | `FileReceiveCard.Reject` 只对本卡片正在打开、直接归属本窗口且属于本进程的原生弹窗发送关闭消息；结束后的目录按钮操作直接返回，目录选择异常只在卡片提示。实际打开 `OpenFolderDialog` 后取消请求，验证无需测试清理即可关闭、主窗口恢复启用、请求返回 null，过期卡片不能重新打开选择器或接收。 |

修复前代码重新编译后，同一组对抗性断言同时复现这两项失败，日志为 `baseline-recompiled.log`；修复后 Debug 和 Release 对应流程通过。

测试也修正了四类取证问题：目录对话框退出前后的观察时序、不能依赖资源管理器窗口标题判定真实目录、发送取消断线后需要重新配对才能继续测试，以及前次发送后浮窗可能正常收起，下一次点击前需要重新显示。另一次基线复制保留旧时间戳导致增量编译未重编，不能作为基线证据；已强制更新隔离副本时间戳重新编译，采用上述真正失败的基线日志。没有通过删除断言或把测试清理当成产品关闭来获得通过。

## 全部剩余限制与待优化项

1. **双机验收尚未完成**：本机回环不能证明另一台 Windows 上能够可靠抢到前台并提醒用户；接收端必须运行包含本功能的新版。尚未替换两端日用程序。
2. **同设备取消的连接边界保留**：原有 `LanNode.SendAsync` 异常／取消路径会关闭该设备会话，避免半帧污染；同一设备其他传输可能随连接一起中断。本轮未修改协议，不能把页内双向操作称作完全独立取消。该行为在 HEAD 中已存在；本轮未做完整的双向并发取消实测。
3. **收件列表容量保留**：只展示最近 100 条全部同步记录中的已完成收件；旧收件会随记录淘汰，不能当作永久文件管理器。
4. **可选体验建议未实施**：发送列表逐项移除、重试操作的独立完成反馈、接收请求剩余时间倒计时。本轮没有扩大到这些新功能。
5. **手动收起语义保留**：关闭按钮、Esc／快捷键仍允许用户主动收起窗口；待处理请求保留至处理、取消或到期。失焦不会自动收起等待收件的窗口。
